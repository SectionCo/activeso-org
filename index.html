    Define a struct, get a table. ActiveSo is a small active record–like persistence layer for Go structs, built on Turso. Create, find, save, and delete directly on your Go values — explicit and lightweight.

    Quick start

    A struct maps to a table

    Model uses plural snake_case table names by default — User maps to users. The embedded Record holds ActiveSo's runtime persistence binding and is not a database column. The activeso tag adds constraints when AutoMigrate(ctx) runs.

    maps to

    db tags choose column names; exported fields without one derive a snake_case name. Plain strings, numbers, and booleans read SQL NULL as their Go zero value, keeping rows readable after additive nullable migrations. Use database/sql nullable types, such as sql.NullString, when your application must distinguish NULL from an empty or zero value.

    Timestamps, managed for you

    Embedding activeso.Record promotes CreatedAt and UpdatedAt as UTC time.Time fields. No model fields or tags are required: AutoMigrate(ctx) creates the implicit activeso_created_at and activeso_updated_at columns, including them when it upgrades an existing table.

    CreatedAt / UpdatedAt

    Read the timestamps directly from any record ActiveSo created or loaded.

    Save(ctx)

    Refreshes UpdatedAt after a successful write; CreatedAt stays fixed.

    New tables use CURRENT_TIMESTAMP defaults. ActiveSo installs triggers that backfill legacy tables, update activeso_updated_at whenever data changes—even through direct SQL—and protect the managed values from arbitrary replacement. Bind(value) attaches persistence behavior but does not load timestamps; a later successful Save(ctx) refreshes them.

    Five constraint options

    Constraints live in the struct tag. An unknown activeso constraint causes activeso.Model[T](db) to panic, so schema mistakes are caught during setup.

    OptionAutoMigrate(ctx) behaviorWrite behavior
    not_null Adds NOT NULL when creating a table. ActiveSo refuses to add a new required column to an existing table automatically. Turso rejects NULL values.
    unique Creates a stable unique index named activeso_<table>_<column>_unique. Create and Save check for an existing value first and return an error matching activeso.ErrUnique; the Turso index remains the concurrency-safe authority.
    index Creates a stable non-unique index for the table and column. Makes equality lookups with FindBy eligible to use a Turso index.
    primary_key Declares the field as the table primary key. Sets the identity used by Find, Save, and Delete.
    belongs_to=table(column) Adds REFERENCES table(column) when creating a table or adding a missing nullable column. With foreign-key enforcement enabled, Turso rejects non-NULL values missing from the referenced column.

    If no field has primary_key, ActiveSo uses the field mapped to id. Exactly one primary key is required. Supported types are strings, booleans, signed integers, uint8–uint32, and floats; uint and uint64 are not supported because Turso stores integers as signed 64-bit values.

    Relationships stay explicit

    Use belongs_to=table(column) on the scalar foreign-key field. ActiveSo creates an inline REFERENCES constraint when it creates the table, while your model remains an ordinary Go struct.

    Enable PRAGMA foreign_keys = ON before using models with belongs_to. SQLite-compatible enforcement is connection-specific, so applications using a connection pool must configure every connection. AutoMigrate(ctx) cannot attach a foreign key to an existing column; use a dedicated migration for that schema change.

    The record lifecycle

    Records returned by Create, Find, query methods, or Bind carry Save(ctx) and Delete(ctx) with them — persistence behavior travels on the value itself.

    Create(ctx, value)

    Inserts value, generates an ID when its string ID field is empty, and returns the bound record.

    Save(ctx)

    Updates all persisted fields except the primary key.

    Delete(ctx)

    Deletes a bound record by primary key.

    Bind(value)

    Attaches persistence behavior to an existing record pointer, such as one loaded outside ActiveSo. It does not load timestamps.

    Full lifecycle

    Create, mutate and save, delete — one bound *T from start to finish.

    A record loaded outside ActiveSo must be attached first with Bind(value); an unbound record's Save and Delete return activeso.ErrUnboundRecord. A bound record's ID is captured when it becomes bound and cannot be changed — modifying it makes Save and Delete return activeso.ErrIDChanged; create a new record when you need a new identity.

    Querying, including vectors

    Every call below is actual API surface. FindBy provides a mapped-column equality lookup; parameterized Where chains with OrderBy, Limit, First, and All; and Nearest orders by cosine distance over a Turso vector32 column.

    FindBy(ctx, column, value)

    Loads every record whose mapped column equals value. The column must exist on the model, so ActiveSo never accepts arbitrary SQL here.

    Find(ctx, id)

    Loads the record with id; returns activeso.ErrNotFound when no record exists.

    All(ctx)

    Loads every record from the model's table.

    CreatedAt

    The UTC time when ActiveSo created the record.

    UpdatedAt

    The UTC time of the record's most recent successful update.

    Where(predicate, arguments...)

    Starts a parameterized query — one argument for each ? placeholder.

    First(ctx)

    Loads the first matching result; activeso.ErrNotFound when none match.

    Where + OrderBy + Limit + All(ctx)

    Query parts compose. OrderBy takes a raw SQL expression; Limit takes a positive maximum row count; terminators return bound records.

    Nearest(column, embedding)

    Orders records by cosine distance from a Vector32 in a Turso vector32 column — lower distance is more similar. Vectors can also ride along in Where when the predicate calls vector32(?).

    OrderBy(expression) called after Nearest replaces the vector-distance ordering and discards that ordering's embedding argument.

    Migrations stay deliberate

    AutoMigrate(ctx) is intentionally additive and safe: it creates tables, adds missing nullable columns, and creates tagged unique and ordinary indexes, but never drops data, removes indexes, changes column types, or tightens existing constraints. It can add a foreign key with a newly added nullable column, but cannot attach one to an existing column. Run it during application setup or deployment; normal model initialization and record operations do not require it.

    OperationRequired model changeEffect
    DropUnique(ctx, column)Remove unique from the column's activeso tag.Drops ActiveSo's named unique index.
    DropColumn(ctx, column)Remove the field from the model.Rebuilds the table without the column.
    ChangeColumnType(ctx, column)Change the Go field's type.Rebuilds the table using the newly inferred Turso column type.
    SetNotNull(ctx, column)Add not_null to the field's activeso tag.Rebuilds the table with NOT NULL; it fails if any existing row contains NULL.

    Removing a struct field alone never drops a database column; use DropColumn explicitly. Each column migration changes only its named target. Rebuilds run inside a transaction — unsupported dependencies cause an error, and failed migrations roll back. Run destructive changes during a controlled deployment with a production backup; tables with dependent views, triggers, foreign keys, generated columns, or unsupported primary-key changes need a dedicated migration.

    Four sentinel errors

    Match with errors.Is. Unique conflicts come back as a UniqueError that carries the offending field — activeso: email must be unique.

    • ErrNotFoundA query did not return a matching record.
    • ErrUnboundRecordA record was not created, loaded, or bound through a Model.
    • ErrIDChangedA bound record's primary key was modified.
    • ErrUniqueA value conflicts with a field marked activeso:"unique".

    A working Echo v5 example

    The repository ships a small Echo v5 server with a single page for creating, editing, and deleting users. It creates a local activeso-example.db and listens on localhost:8080.

    go -C example run .
    MethodPathBehavior
    GET/Renders the create form and existing users.
    POST/usersCreates a user from an email address.
    POST/users/:idUpdates a user's email address.
    POST/users/:id/deleteDeletes a user.
